# Analyze Global Cluster

1. Map cloud providers, regions, electable/read-only nodes, zones, shards, and application geographies.
2. Inspect read preference, write locality, latency, and regional failure behavior.
3. Evaluate data residency and workload-routing requirements.
4. Correlate regional degradation with application traffic.
5. Distinguish global-cluster design issues from ordinary replica-set or sharding behavior.
6. Do not change regional placement without explicit authorization.

## Output
- Global Topology
- Locality/Latency Findings
- Failover/Residency Findings
- Application Impact
- Recommended Action
