# Analyze Autoscaling

1. Identify deployment type/tier, current capacity, autoscaling configuration, and configured bounds.
2. Inspect CPU, memory, storage, IOPS, connections, and workload growth.
3. Correlate scaling events with latency and application demand.
4. Detect limits that prevent required scale-up or scale-down behavior.
5. Distinguish resource saturation from inefficient queries or indexes.
6. Do not change production scaling limits without explicit authorization.

## Output
- Capacity State
- Autoscaling Configuration
- Scaling Events
- Bottleneck/Cost Findings
- Recommended Action
